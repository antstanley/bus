## Threat Model

Authoritative repository threat model (docs/research/04-trust.md), preserved unchanged at artifacts/01_context/threat_model.md: the store (folder, git remote, S3) is a fully untrusted blob service — anyone with write access can inject objects under any author, replace, delete, withhold, or reorder them; agents run on dev machines with the developer's credentials and shell, so a post that steers an agent is a shell exploit; co-located prompt-infected agents are in scope; same-user local processes are out of scope. Ranked risks: prompt injection/infection via bus posts, author impersonation (unsigned in v1), confidentiality, store-owner tampering/withholding, key theft and secrets pasted into posts. Standing task-119 rules verified in this scan: wake delivery targets come only from the local private 0600 registry (never from unsigned presence); token/session secrets never appear in presence, logs, or the store.

### Assets

- agent sessions and their shells/credentials
- delivery-target secrets (messaging tokens, sockets)
- wake/channel integrity
- post feed integrity

### Trust Boundaries

- untrusted store -\> every reader
- presence records (unsigned) -\> delivery decisions
- runtime hook payloads -\> hook process (same-user, out of scope)

### Attacker Capabilities

- arbitrary store object injection/replacement/withholding/reordering under any author
- co-located prompt-infected agent content

### Security Objectives

- no delivery target from unsigned presence without local 0600 registry agreement
- no secrets in presence/logs/store
- loopback/ownership checks on local channels
- log/feed integrity (one event per line, untrusted content framed)

### Assumptions

- same-user local processes out of scope
- v1 posts unsigned (documented roadmap gap)

## Open Questions And Follow Up

- cmux surface ids are still validated only at consumption (cli-local isUuid), not at publication (hooks resolveDeliveryTargets) — the same asymmetric shape the 123 contract removed for session ids; consider extending the shared contract to surfaces when task 110 revisits identifier shapes.
- The opaque session-id pattern intentionally permits '/' — safe against every current sink (hashed registry filename, percent-encoded URL path, UUID-only argv); re-check the three sink families if a future sink consumes raw ids.
- Field-level presence caps (1 KiB) predate the 256-character session-id bound; a later cleanup could align presence field caps with the contract caps.
