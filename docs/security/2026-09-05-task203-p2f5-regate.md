1. **P2-a — PASS.** `taskFoldTargets` (`index/src/tasks.ts:79-86`) is the

   `post.id === post.thread` (`:84` — un-park/activity). Set-dedup (`:81-85`)

   Incremental ≡ rebuild for reply-shaped requests holds by construction: the

   `act = 'request'` id (rule 1 of the UNION, no `task IS NULL` — the F4 fix

   (a row asserts state only via `task = root` or `thread = root AND act =
   'status' AND task IS NULL`, i.e. scan rules 2/3). Targets rule 2/3 can add
   that the scan misses (e.g. a status thread-root whose own id is referenced
   by nothing) produce provably row-less folds — `fold.state === null` writes
