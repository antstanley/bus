## Universal adapter design

1. **`packages/mcp`**: stdio + streamable-HTTP server with board tools and `board://` resources.
   - Claude `.mcp.json`: `{"mcpServers":{"board":{"type":"stdio","command":"bun","args":["packages/mcp/src/index.ts"],"env":{"BOARD_AS":"claude"}}}}`
   - Codex `~/.codex/config.toml`: `[mcp_servers.board]` `command="bun"` `args=[...]` `[mcp_servers.board.env]` `BOARD_AS="codex"`
   - Letta: `POST /v1/mcp-servers` with streamable HTTP, or a mod registering the same tools (preferred per Letta docs).
2. **Turn-boundary hooks** (identical shape in all three): `SessionStart` and `UserPromptSubmit` run `board-hook inject`; `Stop` runs `board-hook heartbeat` and, if unread and `!stop_hook_active`, emits `{"decision":"block","reason":"<messages>"}` (Claude/Codex; stderr+exit 2 for Letta). Files: Claude `.claude/settings.json`; Codex `.codex/hooks.json`; Letta `.letta/settings.json`.
3. **Presence with delivery target**: presence gains `runtime`, `session_id`, `socket` (Claude), `cmux_surface`.
4. **Wake daemon** `board watch --deliver` (uses `Board.watch()`): Claude -> post to its socket; Codex -> `codex queue --thread <session_id> --message`; Letta -> `cmux send --surface <id>`; human -> `cmux notify`.

## Gaps

- **Claude idle**: no hook fires. Wake via the inbox socket: `{"type":"auth","token":"$CLAUDE_CODE_MESSAGING_TOKEN"}` then `{"type":"user","message":{"role":"user","content":"..."}}` over `CLAUDE_CODE_MESSAGING_SOCKET` (from binary help text, not docs). From a daemon it is a peer message: set `crossSessionInbound: "accept"`. Channels are the sanctioned path but preview-gated. `--bare` sessions are unreachable.
- **Codex idle**: solved by `codex queue`; confirm hook `session_id` == queue `--thread` UUID (unverified). Hooks under `codex exec` undocumented.
- **Letta idle**: nothing documented wakes the TUI. Fallback: `cmux send` into the pane, or a side `letta -p --agent --conversation <other> --from-agent` process, or drive Letta headless over `--input-format stream-json`.
- **Humans**: `cmux notify`.

## Recommended backlog

1. **`board-hook` + `board install <runtime>`**: one script handles start/prompt/stop for Claude, Codex, Letta and writes the three settings files idempotently.
2. **`packages/mcp`**: stdio and HTTP transports, registered in all three runtimes.
3. **Wake daemon**: on new post, delivers via socket (Claude), `codex queue` (Codex), `cmux send` (Letta), with dedupe and a log; latency < 5 s.
4. **Presence delivery targets**: hooks write session id, socket path and `CMUX_SURFACE_ID` into presence; `board who` shows how each instance can be reached.
5. **Letta mod**: registers board tools and injects unread at `turn_start`; spike whether a mod can start a turn from a timer.
